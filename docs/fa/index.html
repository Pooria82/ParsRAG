بر سر یک صفحه چه می‌آید.

از بارگذاری تا پاسخ، هر مرحله‌ای که به سند شما دست می‌زند روی رایانهٔ خودتان اجرا می‌شود.

  1. ۱

    بارگذاری

    PDF، Word، PowerPoint، تصویر یا متن اضافه کنید. نوع و حجم فایل پیش از خواندن بررسی می‌شود.

  2. ۲

    خواندن و OCR

    لایهٔ متنی مستقیم استخراج می‌شود. صفحه‌های اسکن‌شده و تصاویر با OCR تسرکت و دادهٔ فارسی و انگلیسی خوانده می‌شوند.

  3. ۳

    بخش‌ها

    متن به بخش‌هایی تقسیم می‌شود که فایل و صفحه، اسلاید، بند یا قسمت خود را به خاطر دارند. یک پل کوتاه، صفحه‌های پشت‌سرهم PDF را به هم وصل می‌کند.

  4. ۴

    بردارها

    مدل چندزبانهٔ multilingual-e5 هر بخش را به یک بردار تبدیل می‌کند؛ به‌صورت محلی، روی CPU یا GPU.

  5. ۵

    Qdrant

    بردارها در Qdrant و زیر نام همان گفت‌وگو ذخیره می‌شوند. گفت‌وگو را حذف کنید، بردارهایش هم حذف می‌شوند.

  6. ۶

    پاسخ مستند

    نزدیک‌ترین بخش‌ها همراه پرسش شما به مدل می‌رسند و پاسخ با منابعش برمی‌گردد.

شما تعیین می‌کنید مدل چقدر از خودش بگوید.

سه شیوهٔ پاسخ صریح؛ همان‌هایی که در کادر پیام انتخاب می‌کنید. یک پرسش را ببینید که به سه شکل پاسخ داده می‌شود.

شیوهٔ «فقط اسناد» وقتی شواهد بازیابی‌شده به آستانه نرسد، پاسخ نمی‌دهد. این یک محافظ است، نه تضمین؛ پاسخ‌های مهم را با منابعشان تطبیق دهید.

شما تعیین می‌کنید چه چیزی از رایانه‌تان خارج شود.

استخراج متن، OCR، embedding و جست‌وجوی برداری همیشه محلی‌اند. فقط مدلی که انتخاب می‌کنید تعیین می‌کند پاسخ کجا نوشته شود.

پاسخ روی همین رایانه تولید می‌شود. هیچ پرسش یا بخشی از سند از راه رابط مدل خارج نمی‌شود.

در همهٔ حالت‌ها embedding و Qdrant محلی می‌مانند و کلیدهای API فقط در حافظه یا متغیرهای محیطی نگه داشته می‌شوند، نه در حافظهٔ مرورگر یا لاگ‌ها.

یک قفسه برای هرچه می‌خوانید.

فایل‌های آفیس، اسکن‌ها، داده و کد با ساختارشان خوانده می‌شوند تا ارجاع بتواند به اسلاید یا بخش اشاره کند، نه فقط به نام فایل.

اسناد

.pdf .docx .pptx

استخراج ساختاریافته، همراه با OCR برای صفحه‌های اسکن‌شده یا پرتصویر PDF و تصاویر درون فایل‌های Word و PowerPoint.

تصاویر

.png .jpg .jpeg .webp .bmp .tif .tiff

اعتبارسنجی، نرمال‌سازی و خواندن با OCR فارسی و انگلیسی.

متن و داده

.txt .md .markdown .json .csv .tsv .log

استخراج UTF-8؛ JSON پیش از ایندکس اعتبارسنجی و نرمال می‌شود.

نشانه‌گذاری و پیکربندی

.html .htm .xml .yaml .yml .toml .ini .cfg

متن قابل‌مشاهده از نشانه‌گذاری و متن UTF-8 از فایل‌های پیکربندی.

کد منبع

.py .js .jsx .ts .tsx .css .sql

استخراج UTF-8 همراه با اطلاعات بخش‌ها تا پاسخ بتواند به جای دقیقی از فایل اشاره کند.

به‌طور پیش‌فرض هر گفت‌وگو تا ۱۰ فایل، هر فایل تا ۱۰۰ مبی‌بایت و هر بارگذاری تا ۵۰۰ مبی‌بایت را می‌پذیرد. فایل‌های آفیس از نظر فشرده‌سازی مشکوک بررسی می‌شوند و قالب‌های دودویی پشتیبانی‌نشده به‌جای اشتباه خوانده‌شدن، رد می‌شوند.

از راست به چپ، از چپ به راست.

git clone https://github.com/Pooria82/ParsRAG.git
cd ParsRAG
cp .env.example .env
docker compose --profile local-model up -d qdrant ollama
docker compose --profile local-model run --rm ollama-init
docker compose --profile local-model up -d --build app
